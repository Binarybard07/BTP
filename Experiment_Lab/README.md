# Experiment Lab

A modular, automated strategy experimentation lab for `Backtest_Module`, faithfully replicating the architecture, Jinja2 template-based combination generation, multi-agent queue workflow, spreadsheet design, ranking conventions, and Google Sheets integration of `RM_TM_TF_Combo`.

---

## 1. Simplified Script Naming

Strategy scripts generated by `generator_agent.py` follow the clean convention:
$$\text{<main\_filename>\_<short\_unique\_id>.py}$$

For example:
- `xgboost_regressor_strategy_001.py`
- `xgboost_regressor_strategy_002.py`
- `xgboost_regressor_strategy_003.py`
- ...

No parameter values are cluttered into the filename. The template name defines the `<main_filename>` prefix and a sequential unique ID identifies the run. Complete configuration parameters are cleanly embedded inside each script and stored in `<main_filename>_<short_unique_id>.json`.

---

## 2. Complete Run Component Preservation

All outputs, reports, and artifacts produced by `Backtest_Module` for each run are copied directly into its dedicated folder inside `Experiment_Lab/Backtest_Results/processed/<run_id>/`:

- `summary.json`: Core backtest metrics (CAGR, MaxDD, Sharpe, etc.)
- `dashboard.html`: Interactive HTML performance tearsheet and charts
- `equity.csv`: Historical account equity series
- `nautilus_nav.csv`: Nautilus portfolio NAV series
- `tradebook_backtest.csv` & `tradebook_by_symbol_backtest.csv`: Detailed execution logs
- `orderbook_backtest.csv` & `orderbook_by_symbol_backtest.csv`: Placed and filled orders
- `book_by_stock_backtest.csv` & `book_summary_backtest.txt`: Position analytics
- `staircase/`: Staircase walk-forward logs
- `<run_id>.py` & `<run_id>.json`: Exact strategy script and configuration snapshot

## 3. Single Clean Spreadsheet (`Metrics`)

`metrics.xlsx` contains a **single clean sheet: `Metrics`**.

> [!NOTE]
> **Why did RM_TM_TF_Combo have two sheets (`Metrics` and `Metrics_Portfolio`)?**
> In the original `RM_TM_TF_Combo` codebase, `Metrics` stored the raw backtest results across all combinations, while `Metrics_Portfolio` was an automated sub-selection filter (`create_portfolio_sheet`) that filtered for Sharpe > 0.75 and chose the best Risk-Management / Trade-Management pair per stock to form a combined multi-strategy live portfolio.
> For single-strategy parameter and indicator tuning in `Experiment_Lab`, having a second sheet is redundant. Thus, `metrics.xlsx` is simplified to one comprehensive `Metrics` sheet sorted by composite Score descending.

### Styling & Ranking Conventions
- **Composite Score Formula**:
  $$\text{Score} = 0.5 \times \text{CAGR} + 0.5 \times \text{MaxDD}$$
  - Both CAGR and MaxDD in `summary.json` share identical percentage units. Because MaxDD is a negative percentage, it directly penalizes severe drawdowns.
- Row 1 frozen (`A2`).
- Headers bolded and centered.
- Top performers ($\text{Score} \ge 0$) highlighted in soft green (`#C6EFCE`).

## 5. Autonomous & Parallel Execution (No Flags Required)

Each agent in `Experiment_Lab` is an **autonomous watcher**:
1. At startup, it first processes all pending items in its queue / backlog.
2. It then activates a file watcher (`watchdog.observers.Observer`) to monitor and react to new items in real time.
3. All agents run completely in parallel and independently.

### Running All Agents Together
```bash
# Launches all 4 agents concurrently in parallel:
python Experiment_Lab/run_lab.py
```

### Running Agents Independently
You can also run any agent independently in its own terminal or background session:
```bash
# 1. Generator Agent: watches strategies_templates/non_processed/
python Experiment_Lab/generator_agent.py

# 2. Runner Agent: watches outbox/non_processed/
python Experiment_Lab/runner_agent.py

# 3. Result Agent: watches Backtest_Results/non_processed/
python Experiment_Lab/result_agent.py

# 4. Google Sheets Sync: watches Backtest_Results/metrics.xlsx
python Experiment_Lab/google_sheets.py
```
